# Тетрадь фокуса — установка с нуля

Инструкция для человека, который никогда не открывал Supabase и Vercel. Идём по шагам сверху вниз; каждый шаг занимает пару минут.

Приложение работает и без аккаунтов: можно открыть его локально, и всё будет сохраняться на этом устройстве. Аккаунты нужны для двух вещей — синхронизации между телефоном и ноутбуком и для AI-ассистента.

---

## 0. Что понадобится

| Что | Зачем | Где взять |
|---|---|---|
| Аккаунт GitHub | хранить код, из него деплоит Vercel | github.com |
| Аккаунт Vercel | сайт с адресом вида `https://….vercel.app` | vercel.com, вход через GitHub |
| Аккаунт Supabase | база данных, вход по почте, серверный прокси | supabase.com, вход через GitHub |
| Ключ DeepSeek | AI-ассистент | platform.deepseek.com → API keys |
| Node.js 20+ | только если хотите запускать локально или деплоить функцию | nodejs.org |

## 1. Код в GitHub

Если папка проекта ещё не репозиторий:

```bash
cd "Lumina V2.0"
git init
git add .
git commit -m "feat: тетрадь фокуса"
```

Дальше на github.com → **New repository** → имя любое, приватный → **Create**. GitHub покажет две команды `git remote add origin …` и `git push -u origin main` — выполните их в той же папке.

Файл `.env` в репозиторий не попадёт (он в `.gitignore`), это правильно.

## 2. Supabase: база и вход по почте

### 2.1 Создать проект

1. supabase.com → **New project**.
2. Name — любое, Database password — придумайте и сохраните (он больше нигде не нужен, но потерять нельзя), Region — ближайший к вам (например, Frankfurt).
3. Дождитесь, пока проект поднимется (около минуты).

### 2.2 Создать таблицы

1. В левом меню **SQL Editor** → **New query**.
2. Откройте файл `supabase/migrations/0001_init.sql` из проекта, скопируйте всё содержимое, вставьте в редактор, нажмите **Run**. Внизу должно появиться `Success. No rows returned`.
3. То же самое с файлом `supabase/migrations/0002_assistant.sql`.

Если запустить файл повторно, ничего не сломается: все команды написаны так, чтобы переживать повторный запуск.

### 2.3 Включить вход по коду из письма

1. **Authentication → Providers → Email**: должно быть включено (по умолчанию так).
2. **Authentication → Email Templates → Magic Link**. В тело письма добавьте строку с кодом, например:

   ```html
   <p>Код для входа: <strong>{{ .Token }}</strong></p>
   ```

   Ссылку из шаблона можно оставить — она тоже будет работать. Код удобнее на телефоне: письмо часто открывается в другом браузере, а код вводится прямо в приложении.
3. **Save**.

### 2.4 Скопировать ключи

**Project Settings → API**. Понадобятся два значения:

- **Project URL** — вида `https://abcdefgh.supabase.co`
- **Project API keys → anon public** — длинная строка

Оба публичные: они попадают в браузер, это предусмотрено. Доступ к данным закрывает RLS (правила в миграции), а не секретность ключа.

## 3. Локальный запуск (по желанию)

```bash
npm install
cp .env.example .env
```

Откройте `.env` и вставьте значения из шага 2.4. Затем:

```bash
npm run dev
```

Откроется `http://localhost:5173`. Без `.env` приложение тоже запустится — просто в профиле будет написано, что синхронизация не подключена.

Проверки: `npm test` (тесты), `npm run lint`, `npm run build`.

## 4. AI-ассистент: серверный прокси

Раздел необязательный: по умолчанию ассистент выключен, и без него всё остальное работает. Включение — два действия: секрет на сервере (ниже) и флаг `VITE_ASSISTANT_ENABLED=true` в переменных сборки (шаг 5.3 и README).

Ключ DeepSeek нельзя класть в `.env` и в код — он оказался бы в исходниках страницы, и любой мог бы им пользоваться за ваш счёт. Ключ живёт только в секретах Supabase, а приложение ходит к функции-прокси.

### 4.1 Установить Supabase CLI

```bash
npm install -g supabase
```

Проверка: `supabase --version`.

### 4.2 Привязать проект

```bash
supabase login
supabase link --project-ref abcdefgh
```

`abcdefgh` — часть Project URL до `.supabase.co`. Пароль от базы спросят — это тот, что из шага 2.1.

### 4.3 Положить ключ и задеплоить функцию

```bash
supabase secrets set DEEPSEEK_API_KEY=sk-ваш-ключ
supabase functions deploy ai
```

После этого в **Edge Functions** появится функция `ai`. Лимит — 40 запросов в час на пользователя, счётчик токенов за месяц виден в профиле.

Ассистент отвечает только вошедшим пользователям: без входа кнопка есть, но внутри написано, что нужен аккаунт.

## 5. Деплой на Vercel

1. vercel.com → **Add New… → Project** → выберите репозиторий из шага 1 → **Import**.
2. Framework Preset: Vite (определится сам). Build command `npm run build`, Output `dist` — тоже сами.
3. Раздел **Environment Variables** — добавьте две переменные из шага 2.4:
   - `VITE_SUPABASE_URL`
   - `VITE_SUPABASE_ANON_KEY`

   Ассистента пока не включаем: переменную `VITE_ASSISTANT_ENABLED` не добавляем (см. 5.3).
4. **Deploy**. Через минуту появится адрес вида `https://имя-проекта.vercel.app`.

Каждый следующий `git push` в `main` пересобирает сайт сам.

### 5.1 Разрешить адрес в Supabase

**Authentication → URL Configuration**: в **Site URL** вставьте адрес с Vercel, в **Redirect URLs** добавьте его же со `/**` на конце: `https://имя-проекта.vercel.app/**`. Без этого ссылка из письма не откроет приложение (код при этом работает всё равно).

### 5.3 Включить ассистента (когда понадобится)

Только после раздела 4: добавьте на Vercel переменную `VITE_ASSISTANT_ENABLED` = `true` и нажмите **Redeploy**. Появится кнопка с речевым облаком. Без секрета на сервере включать флаг не нужно — ассистент будет отвечать ошибкой `not_configured`.

## 6. Установить на телефон

Откройте адрес с Vercel в браузере телефона.

**iPhone (Safari):** кнопка «Поделиться» (квадрат со стрелкой) → **На экран «Домой»** → **Добавить**. Иконка появится среди приложений, открывается без адресной строки.

**Android (Chrome):** меню ⋮ → **Установить приложение** (или **Добавить на главный экран**) → **Установить**.

**Ноутбук (Chrome, Edge):** значок установки в правой части адресной строки → **Установить**.

Первый запуск: выбор языка. Дальше **Профиль → Аккаунт и синхронизация**: введите почту → **Прислать код** → код из письма → **Войти**. Сделайте то же на втором устройстве с той же почтой — данные сойдутся сами.

## 7. Проверка, что всё работает

- **Синхронизация:** отметьте блок на телефоне, на ноутбуке нажмите «Синхронизировать сейчас» в профиле (или просто подождите до минуты) — отметка появится.
- **Офлайн:** включите авиарежим, откройте приложение с иконки — всё открывается, отметки ставятся. Выключите авиарежим — через минуту они уедут на сервер.
- **Ассистент (если включён, 5.3):** нажмите кнопку с речевым облаком, напишите «завтра весь день олимпиада, перенеси всё». Ассистент один раз уточнит область действия, затем пришлёт дифф «было — стало» с кнопкой «Применить»; блоки минимума (числа, домашка, чтение) в диффе остаются.
- **Ключ не в бандле:** `npm run build`, затем `grep -r "sk-" dist/` — должно быть пусто.

## 8. Если что-то не так

| Симптом | Что проверить |
|---|---|
| В профиле «Синхронизация не подключена» | На Vercel не заданы переменные `VITE_…`. После добавления нужен **Redeploy**. |
| Код из письма не приходит | Шаблон Magic Link без `{{ .Token }}` (шаг 2.3). Письмо могло уйти в спам. |
| «Не вышло: … relation … does not exist» | Не выполнена миграция (шаг 2.2). |
| Нет кнопки ассистента | Так и задумано: включается флагом `VITE_ASSISTANT_ENABLED=true` (шаг 5.3). |
| Ассистент: `not_configured` | Не задан секрет `DEEPSEEK_API_KEY` или функция не задеплоена (шаг 4.3). |
| Ассистент: `rate_limited` | 40 запросов в час исчерпаны, подождите. |
| Ссылка из письма открывает пустую страницу | Не настроены Redirect URLs (шаг 5.1). Используйте код. |
| На iPhone нет уведомлений | iOS показывает уведомления только установленному на экран приложению, и только после разрешения в настройках. |
